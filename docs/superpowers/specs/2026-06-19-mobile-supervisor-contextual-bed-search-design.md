# 主管手机端工作看板分层搜索设计

## 目标

修复主管手机端工作看板进入款号后床号搜索失效的问题，并让同一个搜索框根据当前页面层级切换搜索范围。

## 当前问题

搜索词只参与款号列表 `filteredStyles` 的计算。进入某个款号后，页面直接遍历 `selectedStyle.beds`，没有使用搜索条件，因此输入床号不会改变当前款号下的床号列表。

## 交互设计

### 款号列表页

- 搜索框提示为“搜索款号或床号”。
- 输入款号时，显示款号匹配的款式。
- 输入床号时，显示包含匹配床号的款式，并保留现有的匹配床号快捷入口。
- 进度筛选继续与搜索条件叠加生效。

### 款号详情页

- 搜索框提示切换为“搜索床号”。
- 搜索范围仅限当前款号下的床号。
- 使用不区分大小写、忽略首尾空格的包含匹配。
- 清空搜索后恢复当前款号下的全部床号。
- 没有匹配结果时显示“没有匹配的床号”，而不是“暂无床号数据”。
- 不搜索扎号，不改变床号抽屉及扎号详情行为。

### 搜索状态

- 款号列表搜索和款号详情搜索使用两个独立状态。
- 进入款号时，床号搜索默认为空，避免列表页的款号关键词错误过滤床号。
- 返回款号列表时，保留原来的款号/床号搜索条件。

## 技术设计

- 在 `dashboardBoardSearch.js` 中新增纯函数，用于过滤指定款号下的床号。
- `MobileSupervisorBoard.vue` 根据是否存在 `selectedStyle` 决定搜索框绑定的状态、提示文本和结果计数。
- 款号详情中的床号列表改为遍历计算后的床号结果，不修改 `selectedStyle.beds` 原始数据。
- 保持 PC 工作看板和后端接口不变。

## 测试

- 纯函数测试：空关键词返回全部床号；床号支持包含匹配、忽略大小写和首尾空格；无匹配返回空数组。
- 组件源码回归测试：存在独立的床号搜索状态、动态搜索提示、过滤后的床号列表和无匹配空状态。
- 运行现有手机主管看板测试、工作看板搜索测试及前端生产构建。

## 验收标准

1. 款号列表页仍可同时搜索款号和床号。
2. 进入款号后，搜索框只过滤当前款号下的床号。
3. 清空床号搜索后恢复全部床号。
4. 返回款号列表后，列表页原搜索条件仍保留。
5. 搜索行为不影响床号抽屉、扎号列表和工序详情。
6. 相关测试及前端构建通过。
