# 系统安全加固设计

## 目标

在保留 JWT 100 年有效期的前提下，修复当前系统中角色越权、敏感配置泄露、本地打印代理暴露、前端动态脚本注入风险和仓库敏感产物误提交风险。

本次不改变现有业务流程，不引入数据库权限表，不修改 JWT 有效期，也不创建 Git 提交。

## 权限模型

角色以当前用户在当前公司的 `user_company.role` 为唯一可信来源。前端 `localStorage` 中的角色只用于界面展示，不能参与服务端授权判断。

### 超级管理员

- 未选择公司时，只能访问平台级公司管理和超级管理员仪表盘。
- 携带 `X-Company-Id` 穿透公司时，保持现有穿透能力。
- 穿透访问仍受公司存在性检查约束。

### 老板 `boss`

- 当前公司内全部业务权限。
- 管理员工、款式、床次、扎单、工序、通知和生产记录。
- 创建、编辑、删除工资调整。
- 审批或拒绝工资调整。
- 创建、确认、打印工资结算。

### 主管 `supervisor`

- 查看生产数据、款式、床次、扎单和相关员工信息。
- 执行扫码、报工审核、退回报工和生产管理操作。
- 创建工资调整。
- 查看、编辑或删除自己提交且仍处于待审批状态的工资调整。
- 不得审批或拒绝工资调整。
- 不得管理公司、员工账号或工资结算。

### 工人 `worker`

- 扫码并为自己提交报工。
- 查看自己的报工记录、工资调整和工资结算记录。
- 不得指定其他工人报工。
- 不得查看全公司记录或执行任何管理操作。

## 后端授权架构

新增集中式公司角色授权组件，负责：

1. 从 `TenantContext` 获取用户和公司。
2. 从 `user_company` 查询启用且未删除的真实角色。
3. 统一判断 `boss`、`supervisor`、`worker`。
4. 区分超级管理员平台访问和公司穿透访问。
5. 权限不足时抛出统一的 403 异常。

Controller 使用 Spring 方法级授权或统一授权组件，不再仅判断“是否超级管理员”。业务 Service 保留对象归属、状态和操作者检查，形成入口权限与业务约束两层保护。

工资调整规则保持现有数据模型：

- 老板和主管可以提交。
- 主管只能操作自己提交的待审批记录。
- 只有老板可以审批或拒绝。
- 工人只能访问 `/my` 并查看自己的记录。

## 多租户保护

- 每个公司业务请求必须有合法 `X-Company-Id`。
- 非超级管理员必须在 `user_company` 中属于该公司且状态正常。
- 角色查询必须同时匹配 `user_id`、`company_id`、`status = 1` 和未删除条件。
- 工人列表查询在服务端强制限定为当前用户，忽略客户端试图传入的其他 `workerId`。
- 跨公司资源继续由 Service 按 `company_id` 二次校验。

## 敏感配置

- `application.yml` 不再提供真实数据库密码和固定 JWT 密钥默认值。
- 本地和生产启动均通过环境变量提供 `DB_PASSWORD` 与 `JWT_SECRET`。
- JWT 有效期保留 `3153600000000` 毫秒。
- `.env.example` 只保留明显不可用于生产的占位值。
- README、CLAUDE 和部署文档删除真实数据库密码、默认生产凭据及带密码的命令。
- 已经暴露的数据库密码和 JWT 密钥需要在部署时人工轮换；代码不能替用户修改服务器密钥。

## 打印代理

打印代理默认仅监听 `127.0.0.1:9876`，避免暴露到局域网。

安全规则：

- CORS 只允许配置的业务站点和本地开发站点。
- 所有打印和打印机列表接口要求 `X-Print-Agent-Key`。
- 密钥由 `PRINT_AGENT_KEY` 环境变量提供；缺失时代理拒绝启动。
- 状态接口可保留无认证，且只返回版本和运行状态。
- 打印机名称必须匹配系统枚举得到的打印机。
- 打印端口必须符合 Windows 打印端口白名单格式，不允许任意命令片段。
- 使用参数化进程调用替代拼接 shell 命令，避免命令注入。
- 限制单次标签数量、字段长度和请求体大小。

前端从本地配置读取打印代理密钥，并随本地打印请求发送。密钥只保护本机代理免受任意网页调用，不作为云端用户身份凭据。

## 前端 XSS 风险收敛

JWT 继续存储在 `localStorage`，以保持长期登录和现有部署方式。

为降低令牌被 XSS 获取的概率：

- 移除运行时从 CDN 加载二维码脚本。
- 使用项目已有的二维码依赖生成内容。
- 移除二维码生成过程中的 `innerHTML` 注入。
- 保持所有业务文本通过 Vue 转义插值输出。
- 不新增 `v-html`。

本次不迁移 HttpOnly Cookie，因为这会同时改变认证协议、跨域策略、刷新机制和部署配置，超出本轮安全修复范围。

## Git 与部署产物保护

扩展 `.gitignore`，排除：

- `.env` 和本地密钥文件。
- 数据库备份。
- 部署 ZIP、构建产物和上传目录。
- 第三方打印机驱动及安装程序。
- Maven、Vite 和 Node 构建目录。

仓库当前没有提交。本次只完善忽略规则，不自动执行首次提交。

## 测试策略

### 后端

- 老板可访问管理接口。
- 主管可执行生产操作和提交工资调整。
- 主管审批或拒绝工资调整返回 403。
- 工人访问员工管理、全公司记录和工资管理返回 403。
- 工人只能查询自己的记录。
- 非本公司用户携带公司 ID 返回 403。
- 超级管理员未穿透和穿透模式保持现有行为。
- JWT 配置测试确认有效期仍为 100 年。

### 打印代理

- 缺失密钥时拒绝启动或拒绝受保护请求。
- 错误密钥返回 401。
- 不允许的 Origin 被拒绝。
- 非法打印机名和非法端口不能进入打印命令。
- 合法请求仍能构建打印数据。

### 前端

- 生产构建成功。
- 二维码打印不依赖远程 CDN。
- 源码不存在二维码相关 `innerHTML` 注入。
- 现有扫码、日期、生产流程和筛选测试保持通过。

## 验收标准

- JWT 有效期仍为 `3153600000000` 毫秒。
- 服务端不再把所有登录用户视为同一权限。
- 主管可以提交工资调整，但不能审批或拒绝。
- 工人无法调用公司管理接口或读取其他工人的数据。
- 源码与文档不包含真实数据库密码或固定生产 JWT 密钥。
- 打印代理只监听本机，受密钥和来源限制，且不拼接用户输入执行 shell。
- 前后端构建、现有测试和新增安全测试全部通过。
