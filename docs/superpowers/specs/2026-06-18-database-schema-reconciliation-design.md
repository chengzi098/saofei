# 数据库结构统一设计

## 目标

以 Java 实体及 MyBatis-Plus 注解为应用契约，对比本地数据库、生产数据库和 SQL 脚本，消除字段缺失与定义漂移，确保新建数据库和已有数据库升级后都能满足当前应用。

## 结构来源

- Java 实体与注解决定应用实际读写的表和字段。
- `schema.sql` 描述全新安装后的最终结构。
- `migration.sql` 对已有数据库执行幂等升级，不删除业务数据。
- 本地库和生产库只作为现状证据，不直接作为唯一标准。

## 实施方式

1. 修正 `schema.sql` 中与实体不一致的最终表结构。
2. 扩充 `migration.sql`，对缺失字段和必要的列属性进行检测后修正。
3. 增加结构契约测试，覆盖本次发现的高风险字段。
4. 在临时数据库中执行完整建库和重复迁移，验证脚本可运行且幂等。
5. 生产环境先执行 `mysqldump` 备份，再上传并执行迁移脚本。
6. 查询 `information_schema` 并检查服务日志，确认生产结构和业务查询恢复。

## 安全边界

- 不删除生产表或业务字段。
- 不覆盖生产数据。
- 列改为 `NOT NULL` 前先回填空值。
- 迁移失败时停止，不重启或替换应用程序。
