## 1. 功能概述

为老板和主管分别提供一个生产进度看板页面，实时展示款式/扎货的生产完成进度、产量趋势和异常预警。

**目标用户：**
- 老板（公司管理员）：查看本公司全局生产概况
- 主管（车间主管）：查看自己负责的扎货进度和操作待办

**核心数据依据：**
- `style`（款式）→ `bed`（床号）→ `bundle`（扎货）→ `bundle_process`（工序快照）→ `work_record`（报工记录）
- 报工免审核直接生效，主管可退回

**各区域详细说明：**

#### 顶部统计卡片（4个）

| 卡片 | 数据来源 | 计算逻辑 |

| 今日完成件数 | work_record | `SUM(quantity)` WHERE `create_time` >= 今日零点 AND `status` != 3(已退回) |

| 工序退回待处理 | 存在 `work_record.status = 3`(已退回) 且对应工序为"未开始" | 橙色 |
| 2天无报工 | 扎货状态为"进行中"，最新报工时间在 2-3 天之间 | 橙色 |

**各区域详细说明：**

#### 顶部统计卡片（3个）

| 卡片 | 数据来源 | 计算逻辑 |
|------|---------|---------|
| 我的扎货总数 | bundle | `COUNT(*)` WHERE `creator_id` = 当前主管ID |
| 今日已完成 | work_record | `SUM(quantity)` WHERE `create_time` >= 今日零点 AND 对应扎货的 creator_id = 当前主管ID AND `status` != 3 |
| 待处理退回 | work_record + bundle_process | 存在退回记录且工序状态恢复为"未开始"的扎货数量（当前主管创建的扎货） |

#### 扎货进度列表

- 按**款式分组**，每组一个折叠面板
- 每组内展示该款式下主管创建的所有扎货
- 每扎一行，显示：扎号、状态标签、件数、尺码、各工序迷你进度条、完成百分比、最近报工信息
- 异常扎货整行背景标红

工序迷你进度条说明：
- 每道工序一个迷你条（宽16px，高4px）
- 已完成 = 绿色，进行中 = 蓝色，未开始 = 灰色
- 横向排列，一目了然看到该扎货做到哪一步了

#### 待处理退回列表

- 展示当前主管创建的扎货中，有退回待处理的条目
- 每条显示：扎号、款号、工序名称、工人姓名、退回原因
- 操作按钮：
  - **重新分配**：将该工序状态重置，工人可重新报工（实际上已自动恢复为"未开始"，此按钮主要是标记已处理）
  - **忽略**：标记为已知晓，从待处理列表移除（软标记，不修改数据）

#### 快捷操作

- 扫码报工 → 跳转到 `/scan-report`
- 分扎管理 → 跳转到 `/bundle`
- 报工记录 → 跳转到 `/work-review`

## 5. 异常预警规则

### 5.1 异常类型定义

| 类型编码 | 类型名称 | 判定条件 | 严重级别 |
|---------|---------|---------|---------|
| 1 | 3天无报工 | 扎货 `status = 1`(进行中)，且最新一条 `work_record.create_time` < 当前时间 - 3天 | 高（红色） |
| 2 | 2天无报工 | 扎货 `status = 1`(进行中)，且最新报工时间在 2-3 天之间 | 中（橙色） |
| 3 | 工序退回待处理 | 存在 `work_record.status = 3`(已退回) 且对应 `bundle_process.status = 0`(未开始) | 中（橙色） |

### 5.2 异常检测时机

- **查询时实时计算**：每次加载看板页面时，基于当前数据状态实时判断
- 不单独存储异常状态，避免数据不一致

### 5.3 老板视角 vs 主管视角的异常

- 老板看全部异常扎货（本公司范围内）
- 主管只看自己创建的扎货的异常

## 6. 数据查询逻辑要点

### 6.1 今日完成件数

```sql
SELECT SUM(quantity) 
FROM work_record 
WHERE company_id = ? 
  AND create_time >= CURDATE() 
  AND status != 3
```

### 6.2 款式完成进度

款式的完成件数 = 该款式下所有扎货的已完成工序数 × 每扎件数？

**简化方案：** 款式的"完成件数" = 该款式下所有已完成的扎货的件数之和

即：一个扎货的所有工序都完成了（`bundle.status = 2`），就算该扎的件数全部完成。

**更精确的方案（采用）：** 款式的"完成件数" = 该款式下所有扎货中，已完成工序对应的工作量换算。但这样计算复杂。

**最终采用方案：** 款式卡片显示的是"已完成扎货的件数总和 / 该款式下所有扎货的件数总和"。进度条按扎货完成比例计算（不按工序步数），因为老板更关心"总共要出多少件，已经出了多少件"。

### 6.3 扎货工序进度

扎货的工序进度 = 已完成工序数 / 总工序数

主管看板中每个扎货显示的就是这个比例。

## 7. 前端技术方案

- **图表库**：使用 ECharts 绘制近7日产量趋势图（柱状图）
- **Element Plus 组件**：`el-card`、`el-drawer`、`el-progress`、`el-badge`、`el-tag`
